### The vision (current, after the "Nithin Uncle Notes")

ExtraWork is a **WhatsApp-first project organisation and change-approval platform for India's
residential construction and interiors industry.** That sector still runs on phone calls,
scattered WhatsApp threads and memory.

**Three parties on every project:**

- **The interior designer or architect.** They are the **primary customer** and the hub
  everything routes through. Only the designer makes actual changes.
- **The construction company.** It can also use the platform directly, and can send requests and
  files over WhatsApp.
- **The homeowner.** They approve changes, can see the full record at any time, and can send
  requests and files over WhatsApp or ask for all past contracts by message.

**Each project works like a shared folder.** It holds:

- the customer;
- the contract value and its full history;
- the timeline and calendar;
- collaborators and the site team;
- plans, spreadsheets and photos;
- one dedicated record of every change request — numbered, priced, scheduled, justified, and
  then approved, declined or sent back for revision.

**How requests move:** construction manager → designer → homeowner. A defensible approval trail
is a side benefit. **The core value is organisation and visibility for an unorganised sector.**
Minimal friction beats feature count.

**Go-to-market:**

- Start with a family-connected firm as the alpha.
- Give early users the product free forever in exchange for feedback.
- Grow through architects' networks, not cold email.
- Monetise later (ads, affiliates, partnerships, maybe a parts marketplace). Monetisation is
  explicitly not a priority.

**Layers of abstraction:** a single project per stakeholder, then many projects per stakeholder,
then a larger ecosystem.

### How this differs from what was built before October

The codebase as of 14 September was a **two-party, contractor-paid change-order ledger**:

- the owner works in a web dashboard;
- field employees text requests that go **straight** to the customer;
- the customer approves on a no-account link;
- evidence PDFs follow.

The engineering underneath is strong and is kept as-is:

- frozen, hashed versions;
- an append-only audit chain;
- integer paise;
- atomic decisions;
- a transactional outbox;
- PostgreSQL row-level security (RLS);
- 578 tests at baseline.

What October changes is **who it's for, what it's for, and how requests route.** It does not
change the evidence machinery. That machinery becomes the "approvals & contracts" folder of
every project.

## 7. Decisions taken (summary; the spec is authoritative)

| #   | Decision                                                                                                                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | A shared project lives in the designer's workspace. Collaborators join with the `COLLABORATOR` role and `project_members` grants, and switch workspaces from the rail. This reuses sessions, `x-organization-id` and RLS unchanged. |
| D2  | Two kinds of people on a project: **collaborators** (accounts, web) and the **site team** (WhatsApp number only).                                                                                                                   |
| D3  | `request_routing`: `DESIGNER_REVIEW` (default) or `AUTO_SEND` (the old behaviour).                                                                                                                                                  |
| D4  | A proposal is a DRAFT with review provenance, not a new status. It may be unpriced; send gating still applies.                                                                                                                      |
| D5  | The homeowner gets a no-account portal link, which is also the reply to "contracts" on WhatsApp.                                                                                                                                    |
| D6  | WhatsApp is a project channel: senders are the site team and customer contacts; messages are classified as requests or content; the project choice sticks for 2 hours; every reply offers a one-word correction.                    |
| D7  | Global phone uniqueness for the site team is dropped. A number is unique per organization; ambiguity is resolved by asking.                                                                                                         |
| D8  | Request numbers carry the project number, e.g. `P-0004-R03`.                                                                                                                                                                        |
| D9  | Room and type of work are frozen terms, emitted into the snapshot only when present.                                                                                                                                                |
| D10 | A broad but safe file allowlist (no legacy macro formats); always downloaded as attachments.                                                                                                                                        |
| D11 | 2 GiB of storage per workspace during the beta (the notes' "10 MB per user" would be three photos).                                                                                                                                 |
| D12 | Google Drive is linked, not synced.                                                                                                                                                                                                 |
| D13 | New workspaces start on a free `BETA` plan; Razorpay is dormant.                                                                                                                                                                    |
| D14 | Reminders are in-app plus email, plus a private ICS feed for phone alerts.                                                                                                                                                          |
| D15 | Tier 1 B (invoiced mark) and Tier 1 C (paste-to-draft) ship in this effort.                                                                                                                                                         |

**Deliberately not done:**

- Google Drive sync, in-browser file editing, file version history;
- ads, affiliates, a marketplace;
- a rename;
- localisation (Vedant: ignore "Code in various");
- push notifications;
- live Meta WhatsApp.

## 9. Recreating the working environment

```bash
git clone https://github.com/l-baguette/extrawork && cd extrawork
git switch feat/three-party-workspace   # or a slice branch
corepack enable && corepack prepare pnpm@11.21.0 --activate
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 pnpm install --frozen-lockfile

# PostgreSQL 16 (Ubuntu sandbox example; on the Mac use Homebrew per README)
su postgres -c "/usr/lib/postgresql/16/bin/initdb -D ~/pg/data -U postgres --auth=trust"
su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D ~/pg/data -l ~/pg/log -o '-c listen_addresses=127.0.0.1 -p 5432' start"
for db in extrawork extrawork_test; do
  psql -h 127.0.0.1 -U postgres -c "create database $db"
  psql -h 127.0.0.1 -U postgres -d $db -c 'CREATE EXTENSION IF NOT EXISTS pgcrypto; CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE EXTENSION IF NOT EXISTS unaccent;'
done

cp .env.example .env
sed -i -E '/^[A-Z_]+=$/d' .env      # empty values fail config validation; remove them
# set DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/extrawork
# add  TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/extrawork_test
pnpm db:migrate
pnpm verify                          # format, lint, typecheck, every vitest project
```

**Notes:**

- **Chromium for the PDF and golden tests:** Playwright 1.49 wants build 1148. If only a newer
  build is installed, symlink it, e.g.
  `ln -s /opt/pw-browsers/chromium_headless_shell-1194 /opt/pw-browsers/chromium_headless_shell-1148`.
  The two "rendered evidence golden" text assertions then fail only because of fonts and
  letter-spacing in that environment; they pass on the Mac.
- **PostgreSQL in the sandbox** stopped twice during the session. If tests fail with
  `ECONNREFUSED 127.0.0.1:5432`, restart it.
- **2 CPUs:** typecheck one package at a time
  (`cd apps/api && npx tsc -p tsconfig.json --noEmit`) and run targeted vitest files before the
  broad suite.
- **Parallel agents:** give each worktree its own database pair, and never point tests at the
  Mac's `.env`.
